# FONTE ÚNICA DOS PORTÕES DO BOT — OS 43.1
#
# FORMATO. Dois níveis, e o que os distingue é a MARGEM:
#
#   NOME-DO-PORTAO        -> ENTRADA  (coluna 0)
#     chave: valor        -> ATRIBUTO (indentado)
#
# Ler um atributo como entrada cria portão fantasma; ler uma entrada como
# atributo apaga o portão. As duas violações são ERRO explícito no leitor
# (test/gates/leitor_fonte_unica.dart), nunca interpretação silenciosa.
#
# QUEM CONSOME ESTE ARQUIVO
#   1) o passo "PORTÃO DE BATIDA NATURAL DO BOT" de .github/workflows/build.yml,
#      que confere o sha256 da suíte e RODA o `executor` declarado aqui — o
#      passo não tem comando próprio, ele obedece a este arquivo;
#   2) a TRAVA em app/test/teste_motor.dart, que confere entrada, sha256, casos,
#      exigências e a EVIDÊNCIA que a execução deixou.
#
# SOBRE O sha256. É o digest dos bytes do arquivo com o CR das sequências CRLF
# removido. O repositório é editado no Windows (core.autocrlf = true) e o CI
# roda em Linux; sem essa normalização o MESMO conteúdo daria dois digests e o
# portão reprovaria por causa do sistema operacional. Ver
# test/gates/sha256_puro.dart — CR solto continua entrando no hash.
#
# SOBRE `exige`. Os números aqui são repetidos, de propósito, nas constantes da
# própria suíte e na TRAVA de teste_motor.dart. Afrouxar um piso exige editar
# os três lugares, e cada um deles reprova sozinho.
