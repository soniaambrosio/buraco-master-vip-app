# FONTE ÚNICA DOS GATES OBRIGATÓRIOS — workflow `ci-os-integracao.yml`.
#
# Este arquivo é lido por DOIS consumidores, e por nenhum outro caminho:
#   1. o passo "Publicar evidência na branch ci-evidencias";
#   2. `scripts/ci/portao_os_integracao.sh`, o agregador final.
#
# É PROIBIDO copiar esta relação para dentro do YAML. A divergência entre a
# lista da evidência e a lista do agregador foi exatamente o defeito CI-02:
# `rankingfn`, `rankingint`, `identint` e `auditident` apareciam na evidência,
# podiam falhar, e o portão final continuava verde porque não os percorria.
#
# Formato aceito pelo agregador: um gate por linha, NA MARGEM; `[A-Za-z0-9_]`
# apenas; linha em branco e linha iniciada por `#` são ignoradas; comentário no
# fim da linha NÃO é aceito (vira nome inválido e reprova a fonte inteira).
#
# A MARGEM É A AUTORIDADE SOBRE QUAIS GATES EXISTEM. Linha INDENTADA é atributo
# do CONTRATO do gate acima dela — nunca um gate. Um nome escrito por engano com
# espaço à esquerda não some da relação em silêncio: ele vira atributo sem valor,
# e o agregador reprova a fonte inteira com exit 2.
#
# --- O CONTRATO DE CONTEÚDO (OS 32) ----------------------------------------
#
# Esta fonte respondia duas das três perguntas que um portão precisa fazer sobre
# uma suíte obrigatória — o arquivo está lá? ela foi executada? — e não fazia a
# terceira: ELA AINDA PROVA? Trocar o corpo de uma suíte protegida por um único
# `expect(1, 1)`, mantendo nome, caminho e registro, deixava todos os portões
# verdes com dezenas de provas a menos no run. Era o buraco medido na
# rehomologação da OS 30, em outra linhagem, e ele valia aqui igual.
#
# O contrato mora AQUI, indentado sob o gate, e não dentro da suíte: uma guarda
# que vive no arquivo que ela guarda some junto com ele. Atualizar a suíte de
# verdade passa a exigir atualizar estas linhas de propósito — o que aparece no
# diff, que é o ponto.
#
#   <gate>
#       suite      <caminho relativo à raiz do repo>          (REPETÍVEL)
#       executor   <trecho literal que o workflow tem de conter>
#       sha256     <64 hex do conteúdo, com TODO CR removido>
#       provas     <piso ESTÁTICO de declarações de caso>
#       conta      <ERE das declarações>      (opcional; padrão = Dart)
#       casos      <piso de casos EXECUTADOS, lido do log>   (opcional)
#       contador   <ERE com número, no log>   (opcional; padrão = `+N` do Flutter)
#       exige      <literal de código que tem de continuar lá>   (repetível)
#       alvo       <manifesto que o executor roda>            (opcional)
#       exigealvo  <literal que tem de continuar no alvo>     (repetível; exige `alvo`)
#
# UM GATE PODE GUARDAR MAIS DE UMA SUÍTE (OS 40-C1). `suite` é repetível, e
# `sha256`/`provas`/`conta`/`exige` pertencem à suíte declarada ACIMA deles. Os
# demais atributos são do gate e podem vir em qualquer ordem. Um gate de codebase
# — `npm test` e parentes — roda vários arquivos, e até esta OS a metade não
# declarada ficava sem digest, sem piso e sem `exige`.
#
# `alvo` É PARA QUANDO O EXECUTOR NÃO NOMEIA O ARQUIVO. Um passo que roda
# `npm test` não cita suíte nenhuma: quem as nomeia é o `package.json`. Sem
# `alvo`, um gate desses só entraria no contrato AFROUXANDO a exigência de que o
# executor cite a suíte. `alvo` fecha a cadeia elo por elo, em vez de afrouxar:
# o executor cita o diretório do alvo, o alvo nomeia CADA `suite` declarada, e
# `exigealvo` congela o comando oficial. O alvo não tem `sha256` de propósito —
# um `package.json` muda por bump de dependência, e digest que reprova a cada
# bump vira pressão para afrouxar a guarda.
#
# Quem INTERPRETA o contrato é `scripts/ci/verificar_contrato_suites.sh`, que
# falha por conta própria antes de qualquer teste rodar, e cuja matriz é o gate
# `contratosui`. O agregador só atravessa o contrato e confere a FORMA — se ele
# conhecesse o vocabulário, o vocabulário estaria escrito em dois lugares.
#
# MUDOU A SUÍTE DE PROPÓSITO? Atualize `sha256` (o verificador imprime o digest
# que achou) e, se o contrato mudou, `provas`/`casos`/`exige`, no MESMO commit.
# Não há atalho automático de propósito: se atualizar a assinatura fosse efeito
# colateral de rodar o gate, ela não guardaria nada.
#
# Ausência de resultado, marcador `nao_<gate>`, exit code vazio, ilegível ou
# não numérico REPROVAM. Só `exit_<gate>` valendo exatamente `0` fica verde.
#
# `colevid` (gerador de PNG de evidência visual) NÃO entra aqui, por decisão
# registrada no cabeçalho do próprio teste: ele depende de fonte do sistema e
# não afirma regressão. Continua rodando e sendo reportado como informativo.
